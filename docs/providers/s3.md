# S3 object storage

WorldFixture uses SeaweedFS 4.41 as its standalone S3 service. It does not use
the S3 code in `@emulators/aws`.

| Question | Answer |
| --- | --- |
| Overall API status | **Supported but partial** |
| Contract-tested operations | Bucket head and list; object put, get, list, and delete |
| Production comparison | **Not verified against the production provider** |
| Workbench | Live object list and put |
| State | Writes persist for the life of the world |
| Reset | Restarts the service and restores seeded state under `/tmp` |
| Implementation owner | SeaweedFS service with WorldFixture seed and readiness code |

“Partial” means that the tested operations below work. WorldFixture does not
claim the complete Amazon S3 API.

## What works

You can list the generated buckets and their objects. You can put, get, and
delete an object. The Workbench uses the same object store.

## What does not work

WorldFixture does not provide S3 notifications or webhooks. It does not promise
multipart upload, copy, versioning, ACL, policy, lifecycle, tag, or bucket
management behavior.

## Connection and authentication

Use these generated bindings:

| Binding | Purpose |
| --- | --- |
| `S3_BASE_URL` | Browser or host URL with the dynamic S3 port |
| `S3_ACCESS_KEY_ID` | Run identity access key |
| `S3_SECRET_ACCESS_KEY` | Run identity signing secret |
| `S3_REGION` | Region value |
| `S3_BUCKET` | Seeded bucket name |
| `S3_PATH_STYLE=true` | Required endpoint style for local clients |

Requests require a valid AWS SigV4 signature made with the run credentials.
The protocol test verifies that unsigned requests, forged signatures, and an
expired URL with a forged signature return 403. It does not test expiry with an
otherwise valid presigned signature. The runtime, Workbench, and Notion upload
adapter sign their object-store requests with those same credentials.

## Tested operations

| HTTP method and path | Required input | Important response data | Proof |
| --- | --- | --- | --- |
| `HEAD /:bucket` | Existing bucket name | 200 for a seeded bucket; 404 for a missing bucket | Protocol test |
| `GET /:bucket?list-type=2` | Bucket name; optional S3 list query values | XML with `Key`, `Size`, and `KeyCount` | Protocol test |
| `PUT /:bucket/:key` | Object bytes; optional `Content-Type` and metadata headers | 200 and object `ETag` | Protocol test |
| `GET /:bucket/:key` | Bucket and key | Exact object bytes, `Content-Type`, MD5 `ETag`, and WorldFixture metadata | Protocol test |
| `DELETE /:bucket/:key` | Bucket and key | 204; a later get returns 404 | Protocol test |
| `GET /` | Valid run signature | S3 XML with exactly the source-declared buckets | Protocol test |

`GET /` returns the buckets owned by the run identity. The seed uses that same
identity to create each source-declared bucket.

## Registered by SeaweedFS but not proved here

SeaweedFS can expose more S3 operations. WorldFixture has no product contract
test for those operations. Multipart upload, copy, range reads, conditional
requests, versioning, ACLs, policies, lifecycle rules, object tags, bucket
create/delete, and presigned upload are **Not verified against the production
provider**. Do not use them as stable WorldFixture contracts.

S3 notifications, event delivery, and webhooks are **Not supported**.

## Workbench and SDKs

The Workbench lists and writes the same SeaweedFS state that S3 clients use.
There is no separate Workbench object store.

No AWS SDK, `boto3`, or AWS CLI version has a provider contract test. Clients
must use path-style access and the generated dynamic endpoint. SDK operations
outside the tested table are **Not verified against the production provider**.

## Evidence and authority

The protocol test checks seeded keys and sizes, exact bytes, `Content-Type`,
MD5 `ETag`, WorldFixture metadata, exact bucket enumeration, a
put/read/list/delete cycle, signature enforcement, and readiness.

Tests: `emulators/s3/test/protocol-test.mjs`, compiler contract tests under
`tests/contracts/`, `runtime/src/resolve.test.mjs`, and
`runtime/src/supervisor.test.mjs`.

Authority: [Amazon S3 API Reference](https://docs.aws.amazon.com/AmazonS3/latest/API/Welcome.html).
